# Manual Structure and Information Architecture

## Design principles
- Organize around user goals and tasks, not internal code modules alone.
- Put common tasks before rare administrative tasks.
- Separate role-specific instructions where permissions or screens differ.
- Keep conceptual explanation short and place it before the related procedure.
- Use consistent chapter and task identifiers (for example, 5.1, 5.2).
- Give every procedure a unique title and a clear completion condition.

## Recommended outline
1. Cover and document control
2. Contents
3. About this manual
   - Purpose and scope
   - Intended audience
   - Conventions, icons, warnings
   - Related references
4. System overview
   - What the system is for
   - Main navigation and screen layout
   - Roles and permissions
5. Access and preparation
   - Requirements
   - Account/access
   - Sign-in/sign-out
   - First-time setup
6. Task-based procedures
   - Start each task with goal, prerequisites, role, and expected result
   - Include normal path, optional path, decision branches, and recovery
7. Outputs and records
   - View, save, export, download, print, share
8. Troubleshooting and FAQ
9. Glossary
10. Appendices
11. Change history and approval record

## Document control fields
| Field | Guidance |
|---|---|
| Document title | Use the official system name |
| System version | Exact observed or supplied version |
| Manual version | Start at 1.0 or Draft 0.1 |
| Status | Draft for Review / Reviewed / Approved |
| Publication date | Actual generation or publication date |
| Document owner | Only if provided |
| Prepared/reviewed/approved by | Never invent names |
| Change history | Version, date, change summary, author if known |

## Procedure anatomy
- Procedure ID and title
- Purpose / user outcome
- Applicable role
- Prerequisites
- Inputs or required files
- Numbered instructions
- Screenshot(s) with matching markers
- Expected result / completion test
- Alternate path or decision
- Troubleshooting / recovery
- Related procedures

## Warnings and notes
Use consistent labels:
- **Important:** affects successful completion or data integrity.
- **Warning:** potential loss, disclosure, or irreversible action.
- **Note:** helpful context or clarification.
- **Tip:** optional efficiency improvement.
Do not overuse callouts. Use a warning only where a genuine risk exists.
